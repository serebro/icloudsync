# icloudsync

[![CI](https://github.com/serebro/icloudsync/actions/workflows/ci.yml/badge.svg)](https://github.com/serebro/icloudsync/actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

CLI на Go, который входит в iCloud (Apple ID + пароль + код 2FA), хранит сессию в файле столько, сколько её принимает Apple, и при каждом запуске зеркалирует **iCloud Drive**, **iCloud Photos** (личная и общая медиатеки) и **общие альбомы** на внешний диск.

> Используется неофициальный веб-API iCloud, тот же, что у icloud.com и у проектов pyicloud/icloudpd. Apple может изменить его в любой момент.

> **Статус:** проверено на настоящем Apple ID: вход с 2FA, Drive, личная медиатека и общие альбомы. SRP сверен с эталонной Python-библиотекой на тест-векторах. Первый `sync` на новый диск лучше запустить с `--dry-run`.
>
> **Ещё не проверено на настоящем iCloud** (есть только модульные тесты с фейковым сервером): размеры `--size`, кроме `original`, `--xmp-sidecar`, `--albums`/`--album`, `--recent`/`--until-found` (в том числе с какого конца библиотеки они начинают) и системная связка ключей. Сначала запускайте их с `--dry-run` и проверяйте результат.

English version: [README.md](README.md).

## Сборка

```sh
go build -o icloudsync .
```

Через Homebrew (macOS и Linux):

```sh
brew tap serebro/icloudsync https://github.com/serebro/icloudsync
brew trust serebro/icloudsync
brew install icloudsync
```

Новые версии Homebrew не загружают формулы из стороннего tap, пока вы ему не доверяете (`Refusing to load formula ... from untrusted tap`). `brew trust serebro/icloudsync` это разрешает; чтобы доверять только этой формуле: `brew trust --formula serebro/icloudsync/icloudsync`.

Либо `go install github.com/serebro/icloudsync@latest`, либо готовый бинарник со страницы [Releases](https://github.com/serebro/icloudsync/releases).

Нужен Go 1.26+. Поддерживаются macOS и Linux.

## Использование

```sh
# 1. Первый вход (интерактивно: пароль, затем 6-значный код с iPhone/Mac или по SMS)
./icloudsync login --apple-id you@example.com

# 2. Синхронизация (запускать сколько угодно раз)
./icloudsync sync --dest /Volumes/Backup/icloud

# Только посмотреть, что изменится
./icloudsync sync --dest /Volumes/Backup/icloud --dry-run

# Свои альбомы: список и зеркалирование выбранных
./icloudsync albums
./icloudsync sync --dest /Volumes/Backup/icloud --only-photos --album "Семья" --album "Поездки/Рим"

# Быстрый инкрементальный запуск: остановиться после 50 уже скачанных фото подряд
./icloudsync sync --dest /Volumes/Backup/icloud --only-photos --until-found 50

# Проверить сессию / выйти
./icloudsync status
./icloudsync logout
```

Флаги `sync`:

| флаг | по умолчанию | |
|---|---|---|
| `--dest DIR` | `$ICLOUDSYNC_DEST` | папка на внешнем диске; **должна существовать** |
| `--only-drive` / `--only-photos` | | синхронизировать только Drive или только Фото (медиатеки и общие альбомы); без флага — всё |
| `--dry-run` | | ничего не пишет и не удаляет (не создаёт даже папку `.icloudsync`) |
| `--no-delete` | | не удалять файлы, исчезнувшие из iCloud |
| `--force-delete` | | снять защиту от удаления больше 25% файлов (при пустом списке из iCloud удалений не будет всё равно) |
| `--trash` | | файлы, исчезнувшие из iCloud, переносятся в `.icloudsync/trash/<время>/`, а не удаляются |
| `--trash-days N` | 0 | вместе с `--trash`: удалять пакеты корзины старше N дней (0 = хранить вечно) |
| `--workers N` | 4 | параллельные загрузки |
| `--debug-log FILE` | | HTTP-трейс; токены, cookie и scnt в нём скрыты |

Флаги для фото:

| флаг | по умолчанию | |
|---|---|---|
| `--size СПИСОК` | `original` | версии через запятую: `original`, `adjusted` (отредактированная), `alternative` (JPEG из пары RAW+JPEG), `medium`, `thumb` |
| `--force-size` | | пропускать фото без нужной версии, а не подставлять оригинал |
| `--xmp-sidecar` | | писать `.xmp`-файл (подпись, описание, ключевые слова, геопозиция, «избранное») для фото, у которых такие данные есть |
| `--albums` / `--album ИМЯ` | | зеркалировать все свои альбомы или названные (флаг повторяется; `Папка/Альбом` или просто имя альбома) в `Photos/Albums/` |
| `--recent N` | | перечислять только первые N фото каждой медиатеки и каждого альбома |
| `--until-found N` | | остановиться после N подряд идущих фото, которые уже скачаны и не изменились |

Флаги уведомлений (см. [Уведомления](#уведомления)): `--notify-script`, `--notify-email`, `--notify-email-from`, `--smtp-host`, `--smtp-port`, `--smtp-username`, `--smtp-no-tls`, `--notify-on`.

## Структура на диске

```
<dest>/
  Drive/...                   дерево папок как в iCloud Drive
  Photos/Primary/2024/05/17/IMG_0001.HEIC   личная медиатека
  Photos/Primary/2024/05/17/IMG_0001_HEVC.MOV   видео-часть Live Photo
  Photos/Shared/2024/05/17/IMG_0002.JPG    общая медиатека iCloud
  Photos/SharedAlbums/<альбом>/2024/05/17/IMG_0003.JPG   «Общие альбомы» (свои и подписки)
  Photos/Albums/<папка>/<альбом>/2024/05/17/IMG_0001.HEIC   свои альбомы (--albums / --album)
  Photos/Primary/2024/05/17/IMG_0001.HEIC.xmp   файл с метаданными (--xmp-sidecar)
  Photos/Primary/2024/05/17/IMG_0001-adjusted.JPG   отредактированная версия (--size original,adjusted)
  .icloudsync/manifest.json   какие файлы принадлежат программе
  .icloudsync/trash/<время>/...   файлы, исчезнувшие из iCloud (--trash)
```

## Как хранится вход

- Файл сессии: `~/Library/Application Support/icloudsync/session.json` на macOS, `~/.config/icloudsync/session.json` на Linux. Права 0600, папка 0700. В файле лежат cookie, session token и trust token от 2FA.
- Срок жизни сессии задаёт Apple, программа его не придумывает. При запуске сессия проверяется. Если Apple её отклонила, выполняется новый вход по паролю с trust token, обычно уже без кода 2FA. Когда истекает и доверие (обычно примерно через 1–2 месяца), снова нужен `icloudsync login` в терминале.
- Пароль по умолчанию **не сохраняется**. Откуда программа его берёт, в таком порядке:
  - `$ICLOUD_PASSWORD`;
  - системная связка ключей: `login --keyring` кладёт пароль в Keychain на macOS (на Linux в Secret Service, например GNOME Keyring или KeePassXC). Если связка недоступна (cron, ssh, заблокированная связка), берётся следующий источник;
  - `login --save-password`: пароль сохраняется **открытым текстом** в файл сессии (0600). Подходит для автоматических запусков на машине без связки ключей;
  - запрос в терминале.
- `--keyring` и `--save-password` нельзя указывать вместе. Сохранение в связку удаляет прежнюю копию в открытом виде. `logout` удаляет и запись в связке (если нет `--keep-password`), а `status` показывает, где хранится пароль.
- Пароль не принимается как флаг командной строки (он попал бы в историю shell и в `ps`).
- За запуск делается не больше одной попытки входа. Если Apple отклонила сохранённый пароль, он удаляется из файла. Так задание по расписанию не заблокирует Apple ID повторными попытками.

## Зеркалирование и защита данных

- Временные сбои сети и Apple (таймауты DNS, 5xx, `TRY_AGAIN_LATER`) повторяются с паузами в сумме до ~2,5 минуты.
- Скачиваются только новые и изменённые файлы (сравниваются etag/checksum и размер). Переименованный в Drive файл переносится на диске без повторного скачивания.
- Удаляются **только** файлы из `manifest.json`, то есть скачанные этой программой. Посторонние файлы в `--dest` не трогаются.
- Удаления выполняются, только если список файлов сервиса получен полностью и без ошибок.
- Удаления блокируются, если исчезло больше 25% файлов (и больше 50 штук); защиту снимает `--force-delete`. Если iCloud вернул пустой список, не удаляется ничего, даже с `--force-delete`.
- Чужие файлы никогда не перезаписываются: если на месте файла из iCloud лежит файл, который программе не принадлежит, файл из iCloud получает суффикс ` (2)`.
- Каждые 30 секунд каждый сервис печатает строку прогресса, чтобы долгий прогон по уже скачанным файлам не выглядел зависшим.
- Если `--dest` не существует, программа завершается с ошибкой и не создаёт папку. Иначе несмонтированный `/Volumes/X` превратился бы в папку на внутреннем диске.
- В манифесте записан Apple ID. Залить в тот же `--dest` зеркало другого аккаунта нельзя.
- Файл сначала пишется во временный `.icloudsync-*.part`, проверяется размер, затем файл переименовывается. Манифест сохраняется раз в 30 секунд и по Ctrl+C. Прерванный первый прогон продолжится с места остановки.
- Имена очищаются под exFAT/FAT32/NTFS (`: * ? " < > |` и т.п.). Имена, совпадающие без учёта регистра, получают суффикс ` (2)`. На FAT32 файлы больше 4 ГБ не помещаются: программа сообщит об этом, лучше использовать exFAT или APFS.

## Уведомления

Запуск без человека не может ввести код 2FA, поэтому он завершается с кодом 3 и, если настроено, сообщает вам:

```sh
./icloudsync sync --dest /Volumes/Backup/icloud \
  --notify-script ~/bin/icloud-alert.sh \
  --notify-email me@example.com --smtp-host smtp.example.com --smtp-username me@example.com
```

- `--notify-script PROG` запускает `PROG`; в его окружении `ICLOUDSYNC_EVENT`, `ICLOUDSYNC_MESSAGE` и `ICLOUDSYNC_APPLE_ID`.
- `--notify-email ADDR` отправляет письмо через `--smtp-host` (порт 587 — STARTTLS, 465 — TLS сразу; `--smtp-no-tls` только для доверенного локального релея). Пароль SMTP берётся из `$ICLOUDSYNC_SMTP_PASSWORD`, не из флага.
- `--notify-on` перечисляет, о чём сообщать: `interaction` (код 3, по умолчанию), `partial` (код 4), `error` (код 1). По Ctrl+C и при неверных аргументах уведомлений нет.
- Сбой уведомления печатается как предупреждение и не меняет код выхода.

## Коды выхода (для cron/launchd)

| код | значение |
|---|---|
| 0 | всё синхронизировано |
| 1 | ошибка (в т.ч. диск не подключён) |
| 2 | неверные аргументы |
| 3 | нужен человек: истёк вход, нужен код 2FA или пароль. Запустите `icloudsync login` |
| 4 | завершено, но часть файлов не скачалась или удаления были заблокированы |
| 130 | прервано по Ctrl+C |

## Подробнее о параметрах фото

- **Размеры.** `--size original,adjusted` скачивает и оригинал, и отредактированную версию (`IMG_1.HEIC` и `IMG_1-adjusted.JPG`; расширение берётся по типу самой версии). У `medium` и `thumb` суффикс есть всегда, у `adjusted` и `alternative` только рядом с оригиналом. У фото без правок вместо отсутствующей версии берётся оригинал, если не указан `--force-size`. Видео всегда оригинал; на общие альбомы `--size` не влияет. Видео Live Photo хранится вместе с полноразмерными версиями.
- **Смена `--size` позже** заменяет основной файл каждого фото на месте. Лишние файлы версии, которую вы больше не просите, удаляются как любые файлы, ушедшие из iCloud (чтобы сохранить их, используйте `--trash` или `--no-delete`). Поэтому `--force-size` в существующем зеркале удалит фото, у которых нет этой версии.
- **Файлы метаданных** создаются локально (результат детерминирован, поэтому неизменённые данные не перезаписываются). Файл получают только фото с подписью, ключевыми словами, геопозицией, пометкой «избранное» или скриншоты. Запуск без `--xmp-sidecar` снова удалит эти файлы, сами фото останутся.
- **Альбомы.** Фото, которое есть и в медиатеке, и в альбоме, хранится по разу в каждом дереве. Альбомы внутри папок становятся вложенными папками. Запрошенный альбом, которого нет, — ошибка, и удаления блокируются.
- **`--recent` / `--until-found`** намеренно делают листинг неполным для медиатек и ваших альбомов: в таком запуске ничего не удаляется, а сверка счётчика пропускается. Общие альбомы и Drive всегда перечисляются полностью. `--until-found N` считает фото (Live Photo и её видео — одно).
- **Корзина.** `--trash` действует только на файлы, исчезнувшие из iCloud; защита от удаления больше 25% и от пустого списка работает по-прежнему. `--dry-run` ничего не создаёт.

## Ограничения

- **Advanced Data Protection.** Если включена расширенная защита данных, в настройках Apple ID должен быть включён «Доступ к данным iCloud через веб». Иначе Drive и Photos будут недоступны.
- Аккаунты китайского региона (`icloud.com.cn`), общие папки Drive и аппаратные ключи безопасности (FIDO) не поддерживаются.
- «Общие альбомы» хранят фото в уменьшенном виде (до 2048 px, видео до 720p) — это то, что Apple отдаёт подписчикам, оригиналов там нет. Если фото есть и в медиатеке, и в общем альбоме, оно будет скачано дважды. Переименованный альбом переносится в новую папку без повторного скачивания.
- Фото скачиваются оригиналами, если `--size` не говорит иное. Пары RAW+JPEG не выравниваются (`alternative` даёт вторую половину пары). Фото из «Недавно удалённых» и «Скрытых» не зеркалируются.
- Пакеты в Drive (`.app`, `.textbundle`, `.workflow`, `.rtfd`, …) сохраняются распакованными папками, как на Mac. iCloud отдаёт их zip-архивом, поэтому изменённый пакет скачивается и заменяется целиком.
